# GymLedger — Combined AI Workflow

## Purpose

This document is the complete operational workflow for building GymLedger with a cost-conscious but quality-oriented AI process.

The key strategy is:

```text
Local-first for cost.
Cloud-assisted for product quality.
Gemini for Android-specific risk.
Codex for final/rescue risk.
ChatGPT as tech lead, product reviewer, prompt architect, and phase planner.
```

Cloud AI is a development tool only. GymLedger runtime is local-first and offline-capable. Optional online-assisted runtime services are allowed only when the active phase explicitly approves them, they are low-cost/free-tier friendly, and the app remains useful without internet. GymLedger must not depend on paid runtime APIs, auth/login/accounts, required cloud sync, Hilt, Retrofit, or multi-module architecture in v1.

## 2. Product and Architecture Non-Negotiables

GymLedger is:

```text
offline-capable
local-first
personal-use oriented
single Android module in v1
APK-installable
English UI only
Room/local data is the source of truth
```

The app may use optional online-assisted services only when `docs/CURRENT_PHASE.md` explicitly allows them.

Online-assisted means:

```text
optional
low-cost / free-tier friendly
cached locally when useful
editable before saving
not required for core app use
not a replacement for local Room data
```

Do not add in v1 unless explicitly approved in the active phase:

```text
backend/cloud runtime code
auth/login/accounts
required cloud sync
paid runtime APIs
Hilt
Retrofit
multi-module architecture
social features
payments/subscriptions
external AI dependency
cloud food database dependency
```

Approved exception pattern for the updated roadmap:

```text
Cloudflare Worker + D1/KV may be used for optional online-assisted lookup phases.
Android must not call external providers directly.
USDA/Open Food Facts provider calls must go through the Worker once the backend phase exists.
The app must continue to work without endpoint/API key/internet.
```

Default Android architecture:

```text
Compose UI
  -> ViewModel
  -> Repository
  -> Room / DataStore / File IO
```

Optional online-assisted architecture, only in approved phases:

```text
Compose UI
  -> ViewModel
  -> Repository
  -> Room local cache / DataStore settings
  -> Remote source
  -> Cloudflare Worker
  -> External provider
```

Backend/Worker architecture, only in approved backend phases:

```text
Cloudflare Worker TypeScript
  -> normalized DTO contract
  -> D1/KV cache if needed
  -> usage/budget guard
  -> USDA / Open Food Facts providers
```

## 3. Tier Framework

| Tier | Meaning | Default tool | When to use |
|---|---|---|---|
| Tier 0 | Docs, triage, planning, prompt prep | ChatGPT, Gemma, local fast model, Go Flash | Handoff, first-error analysis, commit message, plan writing |
| Tier 1 | Local implementation | Devstral, GLM, Qwen Coder | DAOs, repositories, validators, tests, mappers, simple UI, small fixes |
| Tier 2 | Premium implementation | OpenCode Go | Product-critical UI/UX, complex Compose screens, local model loops, dashboard, workout/nutrition UX |
| Tier 3 | Android platform | Gemini Android Studio | Gradle/KSP/Room tooling, Compose Preview, Logcat, permissions, CameraX, SAF, Health Connect, notifications |
| Tier 4 | Premium rescue/final | Codex CLI/App | Repo broken, risky migrations, hard refactors, final review, release gates |

### Rule

```text
Do not escalate because of anxiety.
Escalate because of evidence:
- local model loops
- local output is CRUD-quality and the phase is product-critical
- build fails after two local attempts
- Android Studio/Logcat/Gradle/KSP/permissions are involved
- migration/import/export risk is high
- final release/major phase needs high-confidence review
```

## 7. Universal Phase Loop

Every phase follows this loop.

### Step 0 — Clean state

```bash
git status --short --untracked-files=all
```

Expected:

```text
clean or only intentional local ignored files
```

If not clean, commit/stash before starting.

### Step 1 — Set active phase

Replace:

```text
docs/CURRENT_PHASE.md
```

with the next phase.

### Step 2 — Decide tier

Use the phase matrix below.

### Step 3 — Mini planning

Required for:

```text
Tier 2
Tier 3
Tier 4
schema changes
Room/repository relationships
complex UI
import/export
security/encryption
final QA
```

Save the output to:

```text
docs/IMPLEMENTATION_PLAN.md
```

If docs are local-only, this remains local.

### Step 3.5 — Discovery pass

For repository, Room, DAO, entity, model, import/export, or any phase where existing files matter, run a discovery pass before implementation.

The discovery pass must confirm:
- actual package path is `com.edu.gymledger`
- actual files exist
- current entity fields
- current DAO/repository patterns
- exact files to modify/create
- mismatches between `IMPLEMENTATION_PLAN.md` and the repo

If the agent tries to read `com/gymledger` or invents files, stop the session.

### Step 4 — Builder preflight

The builder must list before editing:

```text
1. Files it intends to modify
2. Why each file is needed
3. Validation command
4. Quality gate
```

Do not approve unrelated files.

### Step 5 — Implement

Approve only listed files.

### Step 6 — Validate

At minimum:

```bash
./gradlew assembleDebug
```

Critical phases:

```bash
./gradlew clean kspDebugKotlin lintDebug testDebugUnitTest assembleDebug
```

Install if UI/runtime changed:

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

### Step 7 — Review with a different model

The model that built the feature should not be the only reviewer.

Examples:

```text
Build with Kimi -> review with DeepSeek V4 Pro / ChatGPT screenshot / Codex if needed
Build local -> review with Qwen27/Nemotron/DeepSeek V4 Pro
Build Gemini -> review with ChatGPT/Codex if risky
```

### Step 8 — Manual QA

Required for UI/platform phases.

### Step 9 — Commit manually

Use exact paths. Avoid `git add .` unless fully reviewed.

### Step 10 — Close session

Move to the next phase only after commit.

## 8. Stop and Escalation Policy

### If local model loops

```text
Stop.
Do not try a third speculative local attempt.
Create handoff.
Escalate to OpenCode Go or Gemini depending on issue.
```

### If build fails

Run:

```bash
./gradlew clean assembleDebug
```

Then extract the first real error.

Escalation:

```text
1. /gym-first-error
2. /gym-debug
3. Gemini Android Studio if Android tooling/platform
4. Codex if still broken or risky
```

### If UI is functional but mediocre

```text
1. screenshot to ChatGPT
2. /gym-ux-plan or /gym-plan-cloud
3. /gym-build-cloud with Qwen3.6 Plus or Kimi K2.6
4. screenshot review again
```

### If implementation touches risky data

```text
1. local planning
2. local build
3. DeepSeek V4 Pro review
4. Codex final if data loss/migration risk
```

## 9. Global Quality Gates

## Scope Gate

```text
Only CURRENT_PHASE.md implemented.
No future phase work.
No unrelated refactors.
No unnecessary dependencies.
No backend/auth/cloud/Hilt/Retrofit/multi-module unless CURRENT_PHASE explicitly approves the backend/cloud exception.
```

## Package and Path Gate

```text
The app package is com.edu.gymledger.
No package com.gymledger.
No imports from com.gymledger.
No files under app/src/main/java/com/gymledger or app/src/test/java/com/gymledger.
Agents must inspect actual repo paths before creating files.
```

Useful check:

```bash
grep -R -nE "package com\.gymledger\b|import com\.gymledger\b" \
  app/src/main/java app/src/test/java || true
```

## Runtime Cost Gate

```text
No paid runtime API.
No cloud dependency required for core app use.
No external AI provider required.
Optional online-assisted services must have local/manual fallback and must be safe to disable.
All premium AI usage is development-only.
```

## Online-Assisted Gate

For phases that explicitly allow online-assisted features:

```text
Online features are optional.
Endpoint/API key must be configurable or absent by default.
No hardcoded private secrets.
Remote results are suggestions, not source of truth.
Remote results must be cached or saved locally before becoming user data.
User can edit fetched/calculated values before saving.
Android must call the GymLedger Worker, not external providers directly.
Provider attribution and approximate labels must be preserved when relevant.
Free-tier/cost guards must be documented for backend phases.
```

For phases that do not explicitly allow online-assisted work:

```text
No network client.
No provider URL.
No backend code.
No remote lookup implementation.
```

## Build Gate

Default:

```bash
./gradlew assembleDebug
```

Critical:

```bash
./gradlew clean kspDebugKotlin lintDebug testDebugUnitTest assembleDebug
```

## UI/Product Gate

For UI phases:

```text
All UI text is English.
Primary action is obvious.
Empty state is useful.
Flow is usable on phone screen.
Inputs do not feel like a generic CRUD form if the phase is product-critical.
Manual QA passes.
```

## Data Safety Gate

For Room/import/export/backup:

```text
No accidental data loss.
No invalid foreign keys.
No destructive migration unless explicitly approved.
Imports validate before writing where practical.
Failed imports do not corrupt existing data.
Backups can restore enough data to be useful.
```

## Photo Estimate Honesty Gate

```text
Estimates labeled approximate.
User can edit before saving.
No claim of exact calorie estimation.
No external AI/API in v1.
```

## Commit Gate

Before commit:

```bash
git status --short --untracked-files=all
git diff --stat
git diff --cached --name-status
```

Commit only if:

```text
validation passed
manual QA passed if required
scope is clean
review is PASS or PASS_WITH_NOTES
```
